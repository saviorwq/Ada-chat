# v1.5 — Local Generation Runtime（本地生成运行时）

> 定位不是「聊天软件加画图按钮」，而是：  
> **Ada Chat Runtime = Local LLM + Local Image + Local Video**（云端供应商仍并行）。  
> Image 路径：**自有 Diffusers Runtime**，**不依赖** SD WebUI / ComfyUI。

## 产品结构

```text
Ada Chat Runtime
├── LLM Runtime      → GGUF worker / Vulkan llama-server
├── Image Runtime    → Diffusers（骨架已落地，默认关闭）
├── Video Runtime    → safetensors bridge
└── Tool Runtime     → 插件 / 工具调用
```

## 原则

1. 不做「接入 WebUI」，做 **Ada Image Runtime**（生命周期自控）。
2. MVP 先对齐 **视频异步 job**；常驻 worker / GPU 调度是下一阶段。
3. **默认关闭**：依赖重、模型大、显存敏感，不能影响普通聊天用户。
4. **模型面要克制**：第一阶段 **SD1.5 + SDXL + Z-Image**；**单 LoRA MVP** 已支持；不急着 Flux / ControlNet / 多 LoRA。

## 当前骨架（已落地）

```text
task=image + local direct + feature flag
  → image job (queued)
  → php backend/image/run_worker.php
  → image_inference_bridge.py  (doctor / scan / generate)
  → ai_data/generated_images/<job>.png
  → poll image_job_status → 生成图片：…/image_file
```

### 启用开关（任选）

- 文件：`ai_data/features/local_image_enabled`
- 环境变量：`ADACHAT_LOCAL_IMAGE=1`

未开启：本地直连文生图仍为 `blocked_local`（与 v1.4 一致）。

### doctor / scan / generate

| 命令 | 用途 |
|------|------|
| `doctor` | 环境：`torch` / `diffusers` / CUDA 等 |
| `scan` | 发现 HF 目录（`config.json` + `.safetensors`） |
| `generate` | 实际出图（one-shot，首版） |

排错优先跑：`python image_inference_bridge.py doctor`

### MVP 范围

| 项 | 说明 |
|----|------|
| 模型 | SD1.5 / SDXL：**Diffusers 目录** 或 **单文件**；**Z-Image**：**Diffusers 目录**；**单 LoRA**（可选适配器） |
| Job | queued → processing → completed/failed |
| 轮询 | `image_job_status` / `image_file` |
| 前端 | `src/ui/image-generate.js` |
| 默认 | **关闭** |

### 非目标（当前不做）

- Flux / ControlNet / **多 LoRA 叠加** / fuse 永久合并  
- Z-Image **ComfyUI 纯 UNET 单文件**（需 Diffusers 整包）  
- 与 LLM 同卡常驻双模型  
- 角色卡绑绘图（见下方「再往后」）  
- 取消 API  

### 单 LoRA MVP

在已加载基座（Z-Image / SD1.5 / SDXL）上挂 **一个** Diffusers 格式适配器，避免再下合并大包。

**放置**（扫描 `models_dir`）：

- 推荐：`{models_dir}/loras/**/*.safetensors`（也接受路径/文件名含 `lora`）
- 体积约 **1MB–800MB**（过小忽略；过大不当 LoRA）
- 主模型扫描仍 **跳过** 文件名含 `lora` 的文件，避免当 checkpoint

**用法**：

1. 设置 → 本地供应商 →「获取模型」扫描（结果含 `image_loras`）  
2. 分类选「图像生成」→ 出现 **LoRA 下拉** + 强度（0.5 / 0.8 / 1.0，默认 0.8）  
3. 无 LoRA 文件时控件隐藏；选「无 LoRA」会 unload，不残留上次适配器  

**配套**：Z-Image LoRA 挂在 `Z-Image-Turbo`（或同族 Diffusers 基座）上；SDXL LoRA 挂 SDXL。依赖需含 **`peft`**（`pip install -U peft` / `requirements-local-image.txt`）；改依赖后需 **重启 Image Worker**。仅 Comfy 专用 key 的权重可能仍加载失败。

**链路**：`input.lora_id` / `lora_scale` → gateway `job.extra` → `image_inference_bridge`：`load_lora_weights` + `set_adapters`；Worker key 含 LoRA，切换时 unload 再加载。

### 本地图生图（I2I）

- UI：图像分类下切到 **「图生图」** 后才允许上传参考图（≤1MB）；可选 **重绘强度** 0.4 / 0.6 / 0.8（默认 0.6）
- 后端：参考图落盘为 `ai_data/image_jobs/<id>_init.png`，payload 带 `gen_mode=img2img`、`init_image`、`strength`
- 桥接：在已加载 T2I 管线上 `AutoPipelineForImage2Image.from_pipe`（`ZImageImg2ImgPipeline` / SD / SDXL），**不二次加载权重**；可与单 LoRA 同用
- **Arc / Z-Image**：T2I 为防黑图把 VAE 钉在 fp32；I2I 编码时强制对齐 VAE dtype（避免 bf16 激活 vs float bias）。`from_pipe` 后**不再**重复 enable offload
- 文生图模式仍禁止上传（提示「支持：无」是预期行为）

### 锁脸 + 换场景/姿态

证件照/半身参考 +「全身 / 马路 / 换装」等提示词时，**经典 Img2Img 无法改构图**。Ada 会：

1. **构图解锁**：自动改走 **文生图** 按提示词出场景与姿态  
2. **锁脸**：用参考图人脸做 InsightFace 换脸（CPU，`ai_data/face_models/`）

依赖：`pip install -U opencv-python-headless insightface onnx onnxruntime`（见 `requirements-local-image.txt`）。首次会下载 `buffalo_l` 与 `inswapper_128.onnx`。改依赖后需 **重启 Image Worker**。参考图需清晰正面人脸；生成图无人脸时会提示锁脸失败（场景图仍会保留）。

**角色库**：见 [`docs/face-identity-character-library.md`](face-identity-character-library.md)（`bind_cid` / `temp_face_ref`；MLP 仅为未训练预留）。

### Z-Image（Diffusers）要点

- Diffusers ≥0.35（本机验证过 0.39 含 `ZImagePipeline`）
- **Arc 推荐**：ModelScope 官方全精度 `Tongyi-MAI/Z-Image-Turbo` → `D:\models\Z-Image-Turbo`（`sequential_cpu_offload` + bf16，已冒烟通过）
- 默认推理改写：Ada 的 `steps=28` / `guidance=7` → Turbo 常用 `8` / `0`
- **Intel Arc ~16GB**：全精度走 XPU sequential offload（偏系统内存、可出图）
- **INT4（`local/Qwen` / Bl4ckSpaces）**：文本塔 bitsandbytes + DiT quanto；**无 CUDA 时只能整链 CPU**（bnb 无 XPU 内核），6B 级极慢，**不建议在 Arc 上日常使用**。依赖：`pip install -U bitsandbytes optimum-quanto`
- 半成品目录（缺 text_encoder / 残片权重）会被扫描跳过
- 改完后需 **重启 Image Worker**
- Comfy 纯 UNET 单文件仍拒绝

## Image Worker 常驻（v0.1）

> **P0 Manager 门面已落地**；**P1 Image Worker 常驻 v0.1 已落地**（见下方与 [`docs/local-runtime-manager.md`](local-runtime-manager.md)）。

### 目标

模型加载一次，后续任务复用；不要每次生图冷启动 Python / Diffusers。

```text
第一次：prepare → 启动 Worker → LOADING → READY → BUSY → generate → READY
第二次：prepare → 复用 Worker → BUSY → generate → READY（reloaded=false）
```

状态：`STOPPED | STARTING | LOADING | READY | BUSY | ERROR | STOPPING`

- `GET http://127.0.0.1:18766/health`
- `POST /generate`（JSON 与 oneshot request 相同）
- 端口：`ADACHAT_IMAGE_WORKER_PORT`（默认 18766）
- `release(image)` **不**杀 Image Worker，也 **不**自动拉回 llama（避免抢显存）

### P1 — Image Worker 常驻化（已完成 v0.1）

现状（升级前）：`PHP → python generate → 加载 → 出图 → 退出`（SDXL 冷启动很痛）。

已实现：常驻 `serve` + PHP `backend/image/worker.php` ensure/代理；失败可回退 oneshot。

### P2 — GPU Manager（显存调度） ⭐⭐⭐⭐

现状：出图前停 Vulkan llama（`runtime_prepare`）；出图后 `release` 保留 Image Worker。

下一阶段可再做：按需 restore LLM、显存预算等——**本 v0.1 不做复杂 Scheduler**。

### P3 — 模型 Metadata + UI 状态 ⭐⭐⭐⭐

现状：路径 hint 扫描够 MVP。

目标示例：

```json
{
  "name": "SDXL Base",
  "type": "image",
  "resolution": "1024",
  "vram": "8-12GB",
  "status": "ready"
}
```

UI 展示：可运行 / 预计显存 / 速度档位。

## 供应商配置（启用后）

1. 本地 + **直连文件**（与聊天共用 `models_dir`）  
2. 模型类型：**🎨 图像生成**  
3. `pip install -r requirements-local-image.txt`  
4. 模型放置：
   - **单文件**（推荐多数用户）：`D:\models\sdxl\xxx.safetensors`（完整 checkpoint，约 ≥1.5GB；文件名含 `sdxl`/`pony`/`illustrious` 会按 SDXL 加载）
   - **Diffusers 目录**：含 `model_index.json` + `unet`/`vae` 等子目录  
   - **LoRA**：`D:\models\loras\xxx.safetensors`（或路径/文件名含 `lora`；见上方「单 LoRA MVP」）
   - 只下一个权重即可，不必下同仓库多个版本

## 验收（骨架 + LoRA + I2I）

1. `doctor` 可报告依赖缺口  
2. flag 关闭时行为与 v1.4 相同  
3. flag 开启 + 依赖/模型齐备后，可走 job 轮询出图（one-shot 可接受）  
4. `scan` 列出 `loras/` 下适配器；UI 图像分类可见下拉  
5. 基座 + LoRA（scale=0.8）出图与无 LoRA 有可见差异；切回「无 LoRA」无残留  
6. （可选）SDXL + SDXL LoRA 烟测一条  
7. 切到「图生图」可上传参考图；本地 Z-Image / SDXL I2I 能出图；文生图模式仍拒绝上传
8. 证件照 +「全身/马路/换装」类提示：自动文生图换景，并尝试锁脸；完成后说明含「已锁脸换景」或锁脸失败原因
